1Custom domain (codecrafix.shop) par website deploy karna

Aapke paas already Hostasia se liya gaya domain hai. Bas GitHub Pages ko usse jodna hai — 5 steps, 15 minute.

Step 1 — GitHub repo banao

  1. github.com par login → New repository.
  2. Repository name: codecrafix-website (jo bhi naam, par yaad rakhna).
  3. Public select karo. ⚠️ Private repo par GitHub Pages free me nahi milta.
  4. Create repository dabao. README/gitignore add mat karo — khaali repo chahiye.

Step 2 — Files upload karo (root me!)

⚠️ Sabse badi galti yahin hoti hai. index.html repo ke root me hona chahiye, kisi folder ke andar nahi.
  1. Repo me Add file → Upload files dabao.
  2. codecrafix-platform folder ke andar ka saara content select karo — folder khud nahi. (Windows: folder kholo → Ctrl+A → drag karo.)
  3. Commit changes dabao.

Upload ke baad repo me aisa dikhna chahiye:

codecrafix-website/          ← repo ka root
├── index.html               ← ROOT me, kisi folder me nahi
├── store.html
├── custom-dev.html
├── publish-app.html
├── tutorials.html
├── privacy.html
├── terms.html
├── CNAME                    ← content: codecrafix.shop
├── .nojekyll                ← dot file, Upload me chhup jaati hai
├── README.md
├── DEPLOYMENT-GUIDE.md
├── deploy-guide.html
├── supabase/
├── assets/
└── images/
⚠️ .nojekyll miss ho gaya? . se shuru hone wali files GitHub ke web upload me dikhti hi nahi. Add file → Create new file → naam likho .nojekyll → content khaali chhodo → Commit. Iske bina kuch assets 404 de sakte hain.

Step 3 — GitHub Pages on karo

  1. Repo → Settings → left sidebar me Pages.
  2. Source = Deploy from a branch.
  3. Branch = main, Folder = / (root) → Save.
  4. 1–2 minute ruko. Page refresh karo — upar green box me URL aa jayegi:
    https://<username>.github.io/codecrafix-website/

Step 4 — CNAME file (repo side)

CNAME file already project me hai aur usme codecrafix.shop likha hai. Verify kar lo:

CNAME file ka content:   codecrafix.shop

⚠ Bas itna hi — https:// nahi, trailing slash nahi, newline ke alawa kuch nahi.

Step 5 — Hostasia DNS records (registrar side)

  1. Hostasia par login → apna domain codecrafix.shop → DNS Management / Manage DNS / DNS Zone Editor (naam thoda alag ho sakta hai).
  2. Pehle purane parking records delete karo — jo bhi A ya CNAME record @ / blank / www par pehle se hai (Hostasia ka default parking IP, parking wala CNAME) usse Delete karo. Yeh step skip karna = domain kabhi GitHub par point nahi karega, chahe kitni bhi der wait karo.
  3. Ab ye 5 records add karo:
#TypeName / HostValue / Points toTTL
1A@185.199.108.153Auto / 3600
2A@185.199.109.153Auto / 3600
3A@185.199.110.153Auto / 3600
4A@185.199.111.153Auto / 3600
5CNAMEwwwbarmanvivek0786.github.ioAuto / 3600
🔄 Naam dhyan se: barmanvivek0786 ki jagah apna GitHub username daalo. Har case me chhota (lowercase) likho. End me dot (.) mat lagao.
  1. Save / Update dabao har record ke baad.
  2. Optional but recommended — IPv6 (AAAA) records bhi add karo:
TypeNameValue
AAAA@2606:50c0:8000::153
AAAA@2606:50c0:8001::153
AAAA@2606:50c0:8002::153
AAAA@2606:50c0:8003::153

Step 6 — Custom domain verify + HTTPS

  1. GitHub → repo → Settings → Pages → Custom domain me codecrafix.shop likho → Save. (Yeh CNAME file se auto-fill ho jayega.)
  2. GitHub apna DNS check chalayega. Green tick aane ka matlab records sahi hain.
  3. Check karo — terminal me:
dig +short codecrafix.shop
# Expected: 185.199.108.153 / .109.153 / .110.153 / .111.153

dig +short www.codecrafix.shop
# Expected: barmanvivek0786.github.io. aur ek IP

dig +short codecrafix.shop NS
# Hostasia ke nameservers dikhne chahiye

dig nahi hai? Online tool use karo: dnschecker.org → A record → codecrafix.shop.

  1. DNS propagate hone me 10 minute se 24 ghante tak lag sakta hai. Jaldi karne ke liye apne router/machine ka DNS cache flush karo:
    • Windows: ipconfig /flushdns
    • macOS: sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder
  2. Enforce HTTPS tick karo. Yeh DNS green tick + certificate issue hone ke baad hi enable hota hai — agar grey hai toh 15–30 min aur ruko, phir refresh karo.
  3. Domain verification (security): GitHub → apna profile → Settings → Pages → Verified domains → Add a domain → codecrafix.shop. GitHub ek TXT record dega, usse Hostasia me add karo, phir Verify dabao. Isse koi aur aapka domain aapke repo par claim nahi kar sakta.
✅ Q1 ho gaya jab: https://codecrafix.shop browser me khule, https://www.codecrafix.shop bhi khule, aur address bar me lock icon dikhe.

3Website, data aur database securely connect karna

Architecture

   Browser (visitor)                     Aap (Vivek)
          │                                   │
          ▼                                   ▼
   codecrafix.shop                     supabase.com dashboard
   (GitHub Pages, static)              (login required)
          │                                   │
          │ anon key                          │ apna account
          ▼                                   ▼
   ┌─────────────────────────────────────────────┐
   │            SUPABASE (Postgres + RLS)              │
   │  products          → anon: READ only               │
   │  custom_orders     → anon: INSERT only             │
   │  app_submissions   → anon: INSERT only             │
   └─────────────────────────────────────────────┘

Do raste, do levels: visitor ka anon key sirf do kaam kar sakta hai. Aapka dashboard login sab kuch kar sakta hai. Yeh farq RLS policies banati hain — database ke andar, server par. Isliye website me koi password rakhne ki zarurat nahi.

Step 1 — Supabase project banao

  1. supabase.com par sign up → New project.
  2. Name: codecrafix · Database password: strong password rakho aur safe jagah save karo (yeh dobara nahi dikhega).
  3. Region: South Asia (Mumbai) — India ke users ke liye fastest.
  4. Create new project. 2 minute provisioning me lagte hain.

Step 2 — schema.sql run karo

  1. Dashboard → SQL Editor → New query.
  2. Is project ki supabase/schema.sql file kholo, poora content copy karo, editor me paste karo.
  3. Run dabao. Green “Success. No rows returned” aana chahiye.

Yeh script: 3 tables banata hai, indexes lagata hai, RLS enable karta hai, aur secure-by-default policies set karti hai — plus 12 sample products seed karti hai.

✅ Purana schema.sql already run kar rakha hai? Toh bhi yeh naya file dobara run kar do. Yeh purani permissive policies ko drop karke sahi wali banata hai, aur aapka data safely rehta hai.

Step 3 — Keys nikalo (aur galat key se bacho!)

Project Settings → API kholo. Wahan teen cheezein dikhengi — dhyan se padho:

FieldKaisa dikhta haiKahan jaayega
Project URLhttps://abcdefghijkl.supabase.co✅ assets/js/config.js
anon / publiceyJ… (long JWT)✅ assets/js/config.js
service_roleeyJ… (long JWT, alag)❌ KAHIN NAHI
🚨 service_role key kabhi na daalo — na config.js me, na kisi HTML/JS me, na kisi GitHub file me. Yeh key saari RLS policies bypass kar deti hai. Static site me jo file hoti hai, woh poora internet padh sakta hai (View Source → Ctrl+F → service_role). Agar galti se push ho gayi ho: Supabase me us key ko rotate karo, aur GitHub history se hatao.

Step 4 — config.js me daalo

assets/js/config.js kholo aur sirf ye 3 lines badlo:

  USE_SUPABASE: true,
  SUPABASE_URL: 'https://abcdefghijkl.supabase.co',
  SUPABASE_ANON_KEY: 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...'

Commit + push karo. Bas. Store ab Supabase se products padhega, aur forms Supabase me likhenge.

💡 Ek hi config file hai — assets/js/config.js. Alag admin panel hatne ke baad keys replicate karne ka koi risk nahi bacha.

Step 5 — RLS policies (public read-only, aap full access)

schema.sql yeh already kar deta hai. Samajhne aur khud verify karne ke liye:

5a. products — public sirf padh sakta hai

-- Purani permissive policy hatao (agar hai)
drop policy if exists "products_public_write" on public.products;

-- Public: sirf SELECT
create policy "products_public_read" on public.products
  for select to anon, authenticated using (true);

-- Aap (logged in): poora access
create policy "products_auth_write" on public.products
  for all to authenticated using (true) with check (true);

Result: visitor product dekh sakta hai ✅, par add/edit/delete nahi kar sakta 🔒.

⚠️ Yeh sabse zaroori fix tha. Project ke purane schema.sql me for all to anon likha tha — matlab koi bhi visitor ek request bhej kar aapke store ka product delete kar sakta tha. Naye file me woh permission hata di gayi hai.

5b. custom_orders — sab submit kar sakein, padhe sirf aap

-- Public: sirf INSERT (form submit karne ke liye)
create policy "orders_insert_public" on public.custom_orders
  for insert to anon, authenticated with check (true);

-- Aap: read / update / delete
create policy "orders_read_auth" on public.custom_orders
  for select to authenticated using (true);

create policy "orders_update_auth" on public.custom_orders
  for update to authenticated using (true) with check (true);

create policy "orders_delete_auth" on public.custom_orders
  for delete to authenticated using (true);

Result: visitor inquiry bhej sakta hai ✅, par kisi ki inquiry padh nahi sakta 🔒. (Isi wajah se customer email aur budget private rehta hai.)

5c. app_submissions — same model

create policy "subs_insert_public" on public.app_submissions
  for insert to anon, authenticated with check (true);

create policy "subs_read_auth" on public.app_submissions
  for select to authenticated using (true);

create policy "subs_update_auth" on public.app_submissions
  for update to authenticated using (true) with check (true);

create policy "subs_delete_auth" on public.app_submissions
  for delete to authenticated using (true);
🔎 Verify karo dashboard me: Authentication → Policies kholo. Har table ke saamne green “RLS enabled” dikhna chahiye, aur products par anon ke liye sirf ek SELECT policy honi chahiye — koi INSERT/UPDATE/DELETE nahi.

Step 6 — Supabase Auth (optional)

Aapko zarurat nahi hai — Table Editor se sab ho jaata hai. Par agar kabhi koi chhota internal tool banana ho jo authenticated role use kare:

  1. Authentication → Users → Add user → apna email + strong password.
  2. Login karne ka code:
/* Supabase Auth login */
fetch(CFG.SUPABASE_URL + '/auth/v1/token?grant_type=password', {
  method: 'POST',
  headers: { 'apikey': CFG.SUPABASE_ANON_KEY, 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: email, password: password })
})
  .then(r => r.json())
  .then(d => { /* d.access_token ko Authorization header me bhejo */ });

Us access_token ko Authorization: Bearer <token> me bhejo — tab RLS automatically authenticated wali policies apply karegi. Yeh optional hai.

Step 7 — Supabase ko domain ke liye allow karo

  1. Authentication → URL Configuration → Site URL = https://codecrafix.shop.
  2. Redirect URLs me add karo: https://codecrafix.shop/** aur https://www.codecrafix.shop/**.
  3. REST API (jo site use karti hai) ke liye CORS me kuch add karne ki zarurat nahi — Supabase har origin se public read/insert allow karta hai; asli control RLS ka hai.

Step 8 — Teeno cheezein connect hain — test karo

  1. https://codecrafix.shop kholo → store me products dikhne chahiye.
  2. Custom Dev page → form bharo (test email se) → Submit.
  3. Supabase → Table Editor → custom_orders → aapki row wahan honi chahiye ✅
  4. Publish App page → form bharo → app_submissions me check karo ✅

Ab security test — browser console me daalo:

const U = CFG.SUPABASE_URL, K = CFG.SUPABASE_ANON_KEY;
const H = { 'apikey': K, 'Authorization': 'Bearer ' + K };

// 1) READ products — allowed hona chahiye (200)
fetch(U + '/rest/v1/products?select=id&limit=1', { headers: H })
  .then(r => console.log('READ        :', r.status, '(200 = ok)'));

// 2) INSERT product — FAIL hona chahiye (401/403)
fetch(U + '/rest/v1/products', {
  method: 'POST',
  headers: { ...H, 'Content-Type': 'application/json' },
  body: JSON.stringify({ id: 'hack-test', title: 'HACK', category: 'apps', price: 0 })
}).then(r => console.log('INSERT      :', r.status, '(401/403 = safe)'));

// 3) READ dusron ki inquiries — FAIL hona chahiye (401/403)
fetch(U + '/rest/v1/custom_orders?select=email', { headers: H })
  .then(r => console.log('READ ORDERS :', r.status, '(401/403 = safe)'));

Kaise padho: 401/403 = RLS kaam kar rahi hai ✅. Agar 201 ya 200 aaye → policies galat hain → schema.sql ka RLS section dobara run karo.

4Security rules — kya public, kya bilkul nahi

CheezPublic site me rakh sakte ho?Kyun
SUPABASE_URL✅ HaanPublic project address hai.

service_role key❌ Kabhi nahiSaari RLS bypass karti hai. Static site me = poora internet dekh sakta hai.
Database password❌ Kabhi nahiSirf server-side secret.

Deploy se pehle khud check karo

# 1) service_role kahin leak hua?
grep -ri "service_role" . --include="*.html" --include="*.js" --include="*.json"

# 2) koi JWT key file me hai?
grep -rnE "eyJ[A-Za-z0-9_-]{20,}" . --include="*.html" --include="*.js"

# 3) koi admin route/link bacha hai?
grep -ri "admin" . --include="*.html" --include="*.js" --include="*.css"
  • Test 1: kuch nahi milna chahiye.
  • Test 2: sirf anon key mil sakti hai (aapke config.js me). service_role dikhe toh galti hai.
  • Test 3: sirf documentation lines. Koi <a>, href ya fetch admin ko point nahi karna chahiye.

8 golden rules

  1. service_role sirf server par. Static site me kabhi nahi.
  2. RLS har table par ON. Policy ke bina table = band darwaza.
  3. Public site ko sirf wahi permission do jo usse chahiye — products: SELECT, forms: INSERT.
  4. Kabhi for all to anon mat likho — usse visitor aapka data delete kar sakta hai.
  5. Likhne ka kaam dashboard se — browser se nahi.
  6. HTTPS on rakho (GitHub Pages → Enforce HTTPS).
  7. Supabase account par 2FA lagao — yeh ab aapka control panel hai.
  8. Purane client-side admin panels theek se band karo. Humne /admin/ poora hata diya — agar pehle wala version kisi subdomain/repo par deploy kiya tha, use bhi delete karo, warna woh purana password gate abhi bhi live hoga.
